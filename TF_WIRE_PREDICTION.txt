THE "BEFORE" VERDICT IS ATTRIBUTED, NOT INFERRED. The test and the arm were
added in the same commit, so there is no separate pre-change run to point at.
It does not need one: across all 14 tests, arm 5 produced EXACTLY ONE failing
assertion, and it is the one #63 added. Every other assertion in the suite --
including the other two the same channel asserts -- passed under this mutant.
Delete the new assertion and nothing in the suite fails, which is what SURVIVED
means. Repo memory attribute-kills-to-a-test-not-a-suite: the failing test, not
the arm's position in the list, is what carries the claim.

GOT 0, WHICH IS THE RIGHT KIND OF WRONG. An empty FFlowVizOpacityCurve is not
"zero opacity" -- it evaluates to 1.0 everywhere, so a dropped curve does not
blank the volume, it silently composites through a flat ramp. The failure had to
be a POINT COUNT rather than a sampled alpha for exactly that reason: sample the
curve and a drop reads as a plausible value.

THE COUNT CHECK GUARDS THE INDEXING, and it earned that on this run. The two
follow-up assertions read Points[1]; against arm 5 that is an empty array. They
are nested under the count check, so the test FAILED rather than crashed -- and
a crash here would have taken the process down and been reported as a truncated
green run (#62), i.e. as a SURVIVOR. The guard is the difference between this
arm scoring killed and scoring a false SURVIVED.

WHY THE FIXTURE'S CURVE IS NOT MakeLinearRamp(). That helper's points are (0,0)
and (1,1), which agree with an empty curve's 1.0-everywhere reading at neither
endpoint usefully and, more to the point, carry no interior shape. The fixture
authors THREE points with an interior (0.5, 0.25) precisely so the assertion can
distinguish "the authored curve arrived" from "a default ramp arrived that
happens to share its endpoints". Repo memory degenerate-data-defeats-assertions.

AND THE CONTROL FIRED FIRST. Channel 2b asserts SetOpacityCurve(...).IsOk()
before the drain, so a REFUSED setter aborts the test instead of leaving the
default empty curve resident -- which is byte-identical to what a dropped curve
produces. Without that control, "resident curve has 0 points" would have been
ambiguous between the seam dropping it and the fixture never setting it.

ALL FOUR BuildLut INPUTS ARE NOW ASSERTED: ColorMap, bReverseColorMap,
ColorBands, Opacity. The seam test carries a note saying so, and saying that a
new input needs both an assertion AND a narrow arm -- because run 2's lesson was
that a compound arm reports one verdict for every claim in its name.
